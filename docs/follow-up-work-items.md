# Press Speak 后续工作记录

记录日期：2026-07-18

这份文档用于记录当前已经识别出的后续工作项，避免只停留在聊天记录里。以下内容不是已承诺的版本计划，而是建议优先级列表，便于后续逐项实现。

## 1. 单实例 / 双实例协调

当前普通权限实例和管理员权限实例可以并存，这在“以管理员模式重启”能力已经可用之后，变成了一个更明确的行为缺口。

建议优先处理的问题：

- 普通实例点击“以管理员模式重启”后，尽量避免长期留下两个同时运行的实例
- 如果已经存在管理员实例，再次通过 `--admin` 或托盘入口启动时，应有明确策略
- 普通实例和管理员实例同时存在时，托盘图标、热键监听和文本注入职责需要避免冲突

建议方向：

- 先做单实例协调或实例发现
- 再决定是“激活已有实例”还是“提示用户已有同权限实例正在运行”

## 2. 权限状态可见性

当前管理员模式已经可用，但用户侧的可见性仍然偏弱。

建议补充：

- 托盘状态中明确显示当前是“普通模式”还是“管理员模式”
- 设置页增加一行当前运行权限说明
- 日志中进一步区分普通启动、参数触发升权、托盘触发升权和用户取消 UAC

## 3. 管理员模式分发体验

现在用户可以通过 `--admin` 启动参数或托盘入口进入管理员模式，但分发体验仍然依赖手工配置。

建议补充：

- 提供一个“管理员模式启动”的快捷方式生成脚本或发布辅助脚本
- 或在本地安装 / 发布流程中同时产出“普通启动”和“管理员启动”两个入口

这样可以减少手工修改快捷方式带来的误配置。

## 4. 高风险 Windows 场景回归

终端相关兼容性问题已经修复，但还有若干高风险输入环境值得继续验证。

建议补测：

- 管理员 `Windows Terminal` / `PowerShell`
- `VS Code` 集成终端中多次切换输入法后的候选框行为
- 远程桌面会话
- 企业 IM 或 Electron 输入框
- 密码框保护是否仍然可靠

## 当前建议优先级

如果只做一项，建议先处理：

1. 单实例 / 双实例协调

原因：

- 这是管理员模式能力上线后最直接的行为缺口
- 它会影响托盘、热键和实例生命周期的一致性
- 处理完之后，再做权限状态展示和管理员启动入口分发会更顺
