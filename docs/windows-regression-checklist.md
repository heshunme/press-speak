# Press Speak Windows 回归检查清单

## 1. 目的

这份清单用于在真实 `Windows 11 x64` 环境下回归验证 `Press Speak` 当前 MVP 主链路，重点覆盖自动化测试无法充分证明的桌面行为：

- 托盘常驻
- 全局 PTT 热键
- 麦克风录音
- 模型下载、解压和校验
- 最终文本写回
- 剪贴板回退
- 设置页保存与重载

建议每次发版前至少完整跑一遍；如果只是修复某个局部问题，也应至少回归对应章节和第 `11` 章的冒烟项。

## 2. 测试环境

建议记录以下环境信息，方便回归结果可比对：

- Windows 版本，例如 `Windows 11 24H2`
- .NET 运行时版本
- 输入法，例如 `微软拼音`
- 麦克风设备名称
- 是否以普通权限运行
- 是否连接远程桌面

## 3. 测试前准备

执行前确认：

- 已能启动应用构建产物
- 测试机具备可用麦克风
- 网络可访问模型下载地址
- 至少准备一个普通文本输入目标，例如 `Notepad`
- 至少准备一个可触发 `SendInput` 失败或受限的目标，用于验证剪贴板回退

建议准备以下测试语句：

- 中文短句：`今天天气不错我们下午两点开会`
- 中英混合：`请帮我打开 VS Code 然后运行 GPT demo`
- 多空格/缩写验证：`G P T   API`

## 4. 安装与首次启动

### 4.1 启动行为

步骤：

1. 启动应用。
2. 观察是否自动进入托盘。
3. 检查是否没有强制弹出主窗口打断当前前台应用。

预期：

- 可以成功启动
- 托盘出现图标
- 没有异常崩溃

### 4.2 托盘菜单

步骤：

1. 左键或右键托盘图标。
2. 打开设置窗口。
3. 触发模型下载或重载入口。
4. 关闭设置窗口。
5. 从托盘退出应用。

预期：

- 托盘菜单可正常展开
- 设置窗口可打开和关闭
- 菜单项点击后有明确反馈
- 退出后进程完全结束，托盘图标消失

## 5. 首次模型准备

### 5.1 自动下载

前置条件：

- 清空本地模型目录，或在一台从未运行过应用的机器上测试
- 开启“自动下载模型”

步骤：

1. 启动应用。
2. 触发一次需要模型的听写流程，或从托盘菜单主动触发模型准备。
3. 观察下载、解压、校验期间的提示。

预期：

- 缺少模型时会自动准备
- 下载失败时有可理解提示，不会导致应用卡死
- 模型准备完成后可以继续听写

### 5.2 本地模型复用

步骤：

1. 在模型已存在的前提下重启应用。
2. 再次触发听写。

预期：

- 不会重复下载
- 模型加载时间明显短于首次下载
- 主链路可直接进入录音和识别

## 6. 热键与录音主链路

### 6.1 默认热键

步骤：

1. 打开一个普通文本输入框，例如 `Notepad`。
2. 按住默认热键 `Alt + Oem3`。
3. 说一句中文短句。
4. 松开热键。

预期：

- 按下时开始录音
- 松开时结束录音
- 录音结束后进入识别并最终写回文本

### 6.2 误触与短录音

步骤：

1. 快速点按热键，不说话。
2. 再次按住热键但保持静音。

预期：

- 极短录音不会写入垃圾文本
- 纯静音场景会提示未检测到有效语音或等价信息
- 应用最终回到可再次录音的空闲状态

### 6.3 尾录延迟

步骤：

1. 将尾录延迟设为明显值，例如 `2` 秒。
2. 说话结束后立刻松开热键。
3. 重复几次，观察句尾是否更完整。

预期：

- 松键后会继续保留配置的尾部录音窗口
- 句尾吞字情况相比零延迟更少

## 7. 文本写回

### 7.1 普通文本框写回

步骤：

1. 在 `Notepad` 中定位光标。
2. 执行一次中文听写。
3. 执行一次中英混合听写。

预期：

- 文本插入到当前光标位置
- 不会把应用自身窗口抢到前台
- 中英文内容顺序正确，无明显乱码

### 7.2 连续多次写回

步骤：

1. 连续完成至少 `5` 次短句听写。
2. 观察每次是否都能回到空闲状态并接受下一次输入。

预期：

- 状态转换稳定
- 不会出现第二次开始后无响应
- 不会把上一次结果重复插入

### 7.3 剪贴板回退

步骤：

1. 开启“剪贴板回退”。
2. 在一个更容易触发 `SendInput` 受限的目标中执行听写。
3. 对比最终是否仍能写入文本。

预期：

- `SendInput` 失败时会尝试回退
- 回退成功时文本仍能落到目标输入框
- 如果回退也失败，应有明确提示而不是静默丢失

## 8. 标点与后处理

### 8.1 标点开关

步骤：

1. 关闭“启用标点”，听写 `今天天气不错我们下午两点开会`。
2. 开启“启用标点”，重复同一句。

预期：

- 关闭时结果保持原始风格
- 开启后最终文本更接近自然断句
- 标点失败时不会阻断写回

### 8.2 通用后处理规则

步骤：

1. 开启后处理规则。
2. 听写或手动构造 `G P T   API` 类似文本。
3. 在规则测试区验证默认规则效果。

预期：

- 多余空格被压缩
- 英文缩写可按默认规则合并
- 规则保存后重开设置页仍可保留

## 9. 设置页

### 9.1 基础项保存

至少验证以下设置项：

- 输入设备
- 热键
- 识别模式
- 单次录音上限
- 尾录延迟
- 自动下载模型
- 剪贴板回退
- 标点开关
- 后处理规则开关
- 流式预览开关

步骤：

1. 修改其中一组设置并保存。
2. 关闭设置页。
3. 重新打开设置页确认值是否保留。
4. 重启应用后再次确认。

预期：

- 保存后立即生效或按设计生效
- 重启后设置仍然存在

### 9.2 热键录入

步骤：

1. 在设置页点击“开始录入”。
2. 输入一个新的组合键。
3. 保存并在外部应用中测试。

预期：

- 可以稳定采集组合键
- 旧热键失效，新热键生效
- 不会误把单个修饰键保存为完整热键

## 10. 边界与兼容性

### 10.1 密码框保护

步骤：

1. 找一个标准密码输入框。
2. 触发听写并观察行为。

预期：

- 应用拒绝注入
- 不会把识别结果写入密码框
- 有适当提示或日志记录

### 10.2 管理员窗口

步骤：

1. 在普通权限启动应用。
2. 打开一个管理员权限程序中的输入框。
3. 触发听写并观察写回行为。

预期：

- 如果无法注入，应表现为明确失败或剪贴板回退结果
- 不应导致应用崩溃或卡死

### 10.3 远程桌面或企业 IM

步骤：

1. 在远程桌面会话或企业 IM 输入框中测试一次短句听写。
2. 观察热键捕获、录音和写回是否异常。

预期：

- 至少能够明确记录“可用 / 部分可用 / 不可用”
- 如果失败，应能区分是热键问题、录音问题还是注入问题

## 11. 最小发版冒烟

如果时间有限，发版前至少跑完以下最小集：

1. 启动后托盘正常
2. 设置页可打开并保存
3. `Notepad` 中完成一次普通中文听写
4. `Notepad` 中完成一次中英混合听写
5. 标点开关开启后再听写一次
6. 后处理规则开启后验证一次 `G P T   API`
7. 退出应用后进程完全结束
